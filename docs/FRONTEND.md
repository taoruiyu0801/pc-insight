# 前端说明 · 工作观察手札（Fieldnotes）

本文件记录桌面前端的设计系统、模块边界、数据可靠性约定和验证方法。产品名称不变，“工作观察手札”只是内部设计概念。

## 设计

米白纸面、墨色文字、少量陶土色强调；细线分区，平面优先，只有真正独立的对象（对话框、抽屉、报告纸面、“此刻”控制条）才使用容器。所有颜色集中在 `apps/desktop/src/styles/tokens.css`，组件只引用语义 token。项目颜色是用户数据，只用作色点和细边，从不作为文字颜色。

三个来自产品本身的视觉特征：

1. **五轨线形标记**：目标、主注意力、辅助上下文、后台任务、工作状态五条长短不一的细线，用于侧栏、报告刊头、空状态、悬浮窗和扩展弹窗。纯装饰，从不编码真实数据。
2. **带边注与细刻度的时间谱**：左侧边注写轨道名与口径（“人的时间”“可见，不计时”“并行，不相加”），右侧是按本地时钟对齐的主/次刻度。片段按真实时长绘制；主注意力轨使用中性纸灰，状态颜色只出现在工作状态轨。
3. **目录式索引**：项目页、项目投入、报告中的投入使用“编号 · 名称 · 引导点 · 数值”的目录排版。
4. **观察报告排版**：报告是一张纸面——刊头、事实性标题、四个关键数字、逐日表、编号观察、带上标脚注的统计口径。

字体：正文使用 Segoe UI / 微软雅黑；标题和重点数字使用 Sitka / Cambria 等系统衬线，中文在已安装思源宋体 / Noto Serif SC 时使用衬线，否则回退到微软雅黑。未打包任何字体文件，不发起网络请求。数字使用 `tabular-nums`。

状态从不只靠颜色：专注 = 方块，打断 = 三角，分心 = 菱形，待确认 = 空心圆，离开 = 短横；时间谱中待确认为斜纹，多个不足 1 像素的不同记录合并为“细竖纹”（图例说明，放大可逐段查看）。

已计算的对比度（WCAG，相对 `--canvas`）：正文墨色 13.8:1，次级文字 5.8:1，陶土 5.4:1，输入框边线 3.7:1（非文字），提示条与标签上的墨色均 ≥ 11:1。

## 数据可靠性约定

- **查询绑定范围**：`SnapshotStore` 按 `start:end` 存储结果。旧日期的慢响应只会写入旧日期；切换中可以继续显示上一日期的内容，但会淡化并注明“下方仍是 X 月 X 日”。
- **历史读取失败**：保留上一日期内容时，失败提示同时注明请求日期和缓存日期，并提供重试；重试进行中禁用按钮，成功后清除提示。历史日期不会因失败而连续自动重试。
- **顺序轮询**：今日快照每 2 秒刷新一次，下一次请求在上一次结束后才开始；同一范围、同一版本的并发请求共享一个 Promise。页面不可见时降为 15 秒，可见时立即刷新。历史日期不轮询，只在写入后或缺失时读取。Tauri 隐藏窗口是否触发 `visibilitychange` 尚未在原生环境验证；即便不触发，也只是保持 2 秒轮询，不影响后端记录。
- **写入与刷新分离**：`executeMutation` 分别报告“写入失败”“已保存但界面刷新失败”。后者会关闭表单并提供“重新读取”，重试只读取、从不重复写入。每个操作有独立的 pending 键（如 `job:<id>`、`project:new`），防止双击与并发互相干扰。
- **七日数据**：周视图读取的就是七个单日缓存项；今日那一项随轮询更新，写入使所有项失效。没有任何刷新由提示文字触发。
- **报告**：预览与 Markdown 由同一个 `ReportModel` 生成。七日汇总由七个单日统计组成：时长逐日相加（深度工作保持按日判断，与 README 一致），最长连续专注取最大值，后台/并行为各日去重值之和（各日不相交，因此等于整周去重值），碎片化按每日无关片段数重算。七天都按各自范围加载完成前，没有模型，导出按钮不可用。
- **设置草稿**：保存前只修改草稿；轮询带来的外部更新在草稿干净时同步、在草稿有修改时保留草稿并提示。离开设置页会询问，开机启动读取失败显示“读取失败 / 重试”而不是“已关闭”，ActivityWatch 导入有自己的日期，0 条新增是中性结果。
- **保存期间的编辑**：本次提交固定点击保存时的内容；保存和刷新期间仍可输入。收尾时按编辑修订号保留后续输入（包括改回原值），并以已提交内容为新基准计算未保存状态。期间的轮询不覆盖草稿，过期快照不参与同步；写入成功但刷新失败仍确认已保存，重试只读取。
- **报告缓存与导出**：预览可以使用当前范围内的缓存，但任何日期读取失败或缓存版本失效都会标注“缓存数据，暂不可导出”。全部日期恢复有效后才开放导出；普通后台轮询不使有效缓存失效，不会反复禁用导出按钮。
- **采集状态**：区分已暂停、休息中、等待第一条采样、采样已停滞（超过 `max(15 s, 采样间隔 × 6)`）、来源异常和正在记录；`recording = true` 本身不代表采集正常。

演示引擎已与 Rust 对齐的部分：碎片化按无关区间并集计数；分心次数按分心区间并集计数；返回的后台任务按查询范围裁剪起止。演示不运行分类引擎：添加规则或纠正只修改页面内存，界面会注明。

会话详情中的范围纠正使用与 Rust 相同的区间覆盖、预览、批次与撤销流程；演示的原始活动对象不被直接修改。学习辅助建议依据明确工具名/域名，未知浏览器页面不冒充 ChatGPT。日报与会话摘要分别标注，当前目标修改不补写历史。通知渲染在当前顶层对话框/抽屉内，保持焦点约束的同时允许点击“重新读取”和“撤销”。

## 浏览器演示与开发夹具

```bash
npm run dev                                       # http://127.0.0.1:1420，从空白开始
```

仅在开发服务器中可用（生产构建与 Tauri 中不包含）：

| 参数 | 作用 |
| --- | --- |
| `?demo=1&fixture=sample` | `tests/fixtures/demo.ts` 中的示例工作日 |
| `?demo=1&fixture=stress&n=5000` | 合成压力数据：24 个项目、长名称、重叠后台任务 |
| `&clock=2026-10-08T16:30` | 冻结时钟，便于截图对比 |
| `&recording=1` | 以“正在记录”状态打开 |
| `&fault=snapshot` / `slow` / `after-write` | 读取失败 / 每次读取 3 秒 / 每次写入后的下一次读取失败 |
| `&widget=1` | 悬浮窗视图 |

## 验证

```bash
npm run check          # TypeScript
npm test               # Vitest：日期/DST、请求竞态、轮询、写入与刷新、报告口径、布局、语义降级
npm run build
npm run test:rust
```

交互与截图（需要本机 Microsoft Edge）：

```bash
npm i --no-save playwright-core@1.56.1
npx vite --config apps/desktop/vite.config.ts --port 1430
node scripts/visual-check.mjs artifacts/fieldnotes-screenshots
node scripts/recovery-check.mjs artifacts/frontend-recovery
node scripts/workflow-check.mjs artifacts/recording-workflow
```

脚本覆盖六个页面、活动详情、项目/规则/任务表单、确认对话框、悬浮窗（四种状态）、扩展弹窗、首次使用、错误、写入后刷新失败、日期切换中的导出、1000×700 / 125% / 150% / 200%、1,000 与 5,000 条活动的压力场景，并把断言结果写入输出目录的 `log.txt`。截图使用合成数据与冻结时钟，不含真实窗口标题或配对码。

`recovery-check.mjs` 专门验证三项状态恢复：三个页面的历史读取失败与重试、设置保存期间的编辑与失败、日/周报告读取失败与写入失效后的恢复。通过显式控制请求完成顺序制造竞态，使用断言检查行为；任一场景失败会以非零状态退出，结果保存在输出目录的 `results.json`。
